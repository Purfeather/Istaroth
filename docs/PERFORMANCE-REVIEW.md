# 核心 DLL 性能审查

基线为 v0.4.0（`bbafcba`），对应 Windows x64 精简发行包。加载器改动已在独立工作树实现，下列 DLL 项目是后续可单独验收的方案。

## 建议顺序

| 优先级 | 代码证据 | 建议与验收方式 |
| --- | --- | --- |
| 1 · 首次绘制 | `SceneBlur::PrepareShaders` 首次创建材质时同步编译顶点和像素着色器。取出原始 HLSL，在同机以相同入口、配置和优化选项编译 11 组，两段合计中位数为 **6.93 ms**。 | 先将这两段着色器移到构建时编译，保留一份 HLSL 源。在离线 DX11 宿主比较首次材质绘制和重建设备资源的耗时，复跑材质测试中的色值、模糊强度和多重采样用例。ImGui 后端另有两处独立编译，6.93 ms 的测量只涵盖项目自有材质。 |
| 2 · 菜单展开时的 GPU 耗时 | `Render` 在仅显示 HUD 时已裁剪模糊范围。菜单展开或渐隐期间传入整张画面，`SceneBlur::Draw` 在缩小后的区域执行三次绘制。 | 在合成场景记录仅 HUD、菜单稳定展开、菜单开合三种状态的 GPU 时间。优先实验按 HUD 与菜单实际可见边界加采样余量裁剪。以 1080p、4K 的 GPU 中位数与 P95、菜单边缘和渐隐截图验收。多重采样分支自带整帧 resolve，需要单列测量。 |
| 3 · HUD 逐帧文字测量 | `DrawTopCenterHud` 每帧测量三个固定标签、Insert 和倍率样本，`DrawBoxedText` 随后又遍历字形求墨迹边界。 | 离线渲染固定帧数，先记录 UI 构建线程时间。测出可重复的占比后，再按字体和字号缓存固定标签的宽高及墨迹边界。动态倍率继续按内容更新，以 DPI 变化和字体重建后的像素对照验收。 |
| 4 · 探测组件的常驻内存 | 正式包中 `story_probe.dll` 只有 122 KiB，PE 的 `.data` 虚拟大小却为 `0x40FAC8` 字节，其中一个静态数组含 1024 个 4096 字节数据页。 | 先在现有离线宿主里测空闲和活动期间的私有工作集、峰值及持续时间，再决定是否值得改存储策略。PE 区段大小只能说明虚拟布局，实际物理驻留量需要单测。 |

相关源码见[模糊材质](../src/resident/resident_material.h)、[渲染入口](../src/resident/resident_renderer.cpp)、[HUD 布局](../src/resident/resident_ui.cpp)、[剧情探测组件](../src/features/story_probe.c)和[材质回归](../tests/material_test.cpp)。

四个发行 DLL 共 1,145,344 字节，其中 `Istaroth.dll` 占 64.5%。按上述材质的纹理描述估算，4K SDR 下全尺寸副本、两张长宽各缩至四分之一的浮点纹理和一张同样缩小的输出纹理，合计约 **41.5 MiB** 像素数据。驱动对齐、资源视图与游戏自身缓冲另计。裁剪绘制范围会改变处理的像素数，纹理尺寸需单独改动才会影响这项估算。

`time_core.dll` 和 `dialogue_actions.dll` 的常规工作循环分别含 10 ms、25 ms 睡眠。若目标是降低后台 CPU，可对现有宿主同时记录线程 CPU 时间、每秒唤醒与停止响应 P95。现有证据只能确认循环周期，尚不足以支持调整间隔。

## 本次加载器改动与测量

| 项目 | v0.4.0 | 界面重构时的测量值 |
| --- | ---: | ---: |
| 四个发行 DLL 完整 SHA-256 校验，热文件缓存 | 1.579 ms | 0.788 ms |
| 640 × 220，同一状态重绘 | 755.70 µs | 9.01 µs |
| 640 × 220，两种状态交替重绘 | 727.75 µs | 363.30 µs |

校验测试使用同一套本机 MSVC 优化选项、正式包原始字节和发布清单。新旧实现交替执行，每组 100 轮，预热后取 9 组中位数，每轮重新建立校验会话并核对四个摘要。读缓冲在一次启动校验中复用，各文件各自计算完整摘要。Windows 提供的 SHA-256 算法句柄可直接用于创建哈希对象。[Microsoft CNG 文档](https://learn.microsoft.com/en-us/windows/win32/seccng/cng-algorithm-pseudo-handles)

绘制测试使用相同的 32 位离屏位图。每组连续绘制 250 次，计入 GDI 批处理刷新，取 7 组中位数。界面使用发行图标、当前操作标题和底部步骤条。错误页显示实际错误码、原因及日志文件名。验证包括 100%、150%、200% 客户区快照、同状态像素一致、状态变化、尺寸变化及缓存释放后的 GDI 对象计数。

表中数据早于后台校验和组件使用前复核。0.788 ms 仅是当时四个文件在热缓存中的校验耗时。当前版本的完整启动时间、真实 GPU 帧时间及设备间差异仍待实机测量。
