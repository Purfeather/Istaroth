# 开发版诊断与全屏验证

本开发版使用 `0.1.2-dev.1` 标识。正式回退版本仍为 v0.1.1。

## 保存和提交错误报告

发生问题后，在工具所在目录打开终端，运行：

```powershell
.\Istaroth.exe --diagnostics
```

加载器会在 `reports` 文件夹生成一份带时间戳的 UTF-8 文本报告，并显示保存位置。该入口无需启动游戏，缺少某份日志或组件也可以导出。静默导出可使用 `--diagnostics --quiet`；退出码 0 表示成功。

报告包含工具版本、源码提交、Windows 版本、支持的游戏指纹、功能配置、组件文件大小，以及现有工具日志。不会写入配置文件中的游戏路径或其他配置段；复制日志时会替换已知的游戏路径、工具目录和当前用户目录。发送前仍可打开文本检查内容，并填写报错时间、时区、弹窗文字和当时场景。

`Istaroth-runtime.log` 和 `Istaroth-injector.log` 各达到 512 KiB 后轮换，保留一份 `.1` 备份。每行记录 UTC 时间、进程和线程、版本及源码标识。运行日志在状态变化时记录，并每 5 秒补充状态快照，包含功能开关、倍率、对话判定、组件错误与渲染状态。

这些记录用于确认故障前最后完成的阶段。进程直接退出、被外部结束或驱动异常时，日志不一定包含异常堆栈；本版不安装全局异常处理器，也不生成游戏内存转储。需要时另附 Windows 可靠性监视器中的技术详细信息。

## DX11 菜单

开发版通过 DXGI 帧回调将菜单和 HUD 绘制到目标游戏交换链，使用原游戏窗口接收菜单输入。打开菜单不激活独立窗口、不改变游戏显示模式。关闭菜单或切换到其他应用时恢复此前的鼠标状态，功能恢复仍经过原有控制器核验。

回调安装、首帧初始化、图形状态保存与恢复、缓冲区尺寸变化、设备失效和交换链释放都有对应日志。初始化未完成时不会报告成功。

## 验证范围

自有宿主使用隐藏窗口和真实 WARP DX11 交换链检查帧回调、图形状态恢复、菜单消息处理、鼠标状态、尺寸变化和交换链重建；设备失效采用模拟返回值。鼠标与焦点 API 在宿主中模拟，不向桌面发送输入。

以下项目需实机验收后才能确认：

- 游戏的实际交换链能否完成首帧初始化，加载器是否正确收到确认。
- 真正独占全屏下 HUD 可见，Insert 打开菜单时保持游戏画面与焦点。
- 菜单按钮、滑块及开关可操作，菜单打开时游戏不会继续响应这些输入。
- Insert／Esc 关闭菜单、Alt+Tab 切换应用及恢复后，鼠标显示、位置与限制正确。
- 游戏内切换分辨率、窗口化、无边框和独占全屏后，菜单能够继续工作。
- 长时间运行、退出游戏及再次启动后的表现；本版不代表已解决其他用户报告的 `(2,0,4)` 退出问题。
